# 実装計画 v2: 売買代金上位50銘柄 × 寄り付き10分 RL エージェント

- 作成: 2026-11-06
- 前提資料: `ai-trading-agent.md`（v1, 7203 単銘柄・15分窓）, オーナー案 `K:\aaaaa.txt`（レビュー済み）
- v1 の結果: `.agents/docs/research/rl-7203-opening10m-results.md`。7203 単独の PPO は「15秒後に1回買って10分で強制決済」に収束し、売買を覚えなかった（テスト PF 0.67）。オーナーの判断は「7203 の歩み値だけでは無理。銘柄を増やす」。

## 1. 確定した要件（オーナー決定）

| 項目 | 決定 |
|---|---|
| 売買時間 | **寄り付き（その銘柄の初約定 T_open）＋10秒 〜 T_open＋10分**。10分時点で強制決済。10秒より前は観測のみ（特徴量計算には使う） |
| 銘柄 | **日ごとに前営業日の売買代金（TurnoverValue）上位50銘柄**。当日の情報で選ばない（先読み防止）。上場廃止銘柄も除外しない（生存バイアス防止） |
| 対象 | 個別株のみ（ETF/ETN/REIT 等は既定で除外、フラグで含められる） |
| 実装場所 | 既存 `src/trading_rl/` を拡張（`src/ai/` は新設しない） |

## 2. v1 / オーナー案からの主な修正

1. **判断間隔は時間単位（1秒ごと）**。tick 単位は 7203 で失敗済み、N ticks 単位は銘柄で時間幅が変わるので不採用。
2. **入力は銘柄非依存**: 価格は率または呼値単位、出来高は「その銘柄の前日までの20日平均」比、時間は経過秒。
3. **コストは呼値ベース**: 東証の呼値表（TOPIX100 構成銘柄は別表）で銘柄・価格ごとの呼値を求め、成行は片道 0.5 呼値の不利約定。
4. **Type 列は前場/後場区分**（売買区分ではない）。買い/売り推定は tick rule。
5. **関門を「予測できるか」に置き換え**: 「Oracle > Random」は常に成立するので判定にならない。
6. **期間ずらし検証（walk-forward）と学習外銘柄での検証を PPO の合格条件に**（v1 の検証好成績は偶然だった）。
7. **画面は既存の「日ごとに事前計算して再生」方式を流用**（`/api/ai/replay-trades`）。

## 3. フェーズ

### P1. 銘柄表とデータ切り出し（実施中）
- `src/trading_rl/universe.py`: 日ごとの上位50表（prev_date, 前日売買代金, 前日終値, 20日平均出来高, TOPIX100 フラグ, 呼値）。
- `src/trading_rl/cache.py` + `scripts/build_rl_dataset.py`: 各（日, 銘柄）の [T_open, T_open+600s] 歩み値をローカル `.cache/trading_rl/` に保存。状態（ok / tick ファイルなし / 寄らず / エラー）を全件記録。
- 完了条件: 2026-08-19 の順位が 08-18 売買代金の手計算と一致、全期間の切り出し完了、読み込み速度の計測。

> **2026-11-06 オーナー決定**: 予測可能性は判断指標にしない。寄り付きスキャルは値動きの予測ではなく、
> 約定値が気配間を行き来する「どさくさ」（ボラティリティ）で数Tick抜く戦略である。
> 下記 P2 は実施済み（成行前提で全ホライズン不合格、`.agents/docs/research/rl-top50-predictability-gate.md`）だが、
> 成行前提では bounce を取れないため本戦略の可否判定には使わない。P3 は指値中心の環境として作り直す。**約定判定は「突き抜けたら約定」（買い指値 P は P 未満の約定、売り指値 P は P 超の約定で成立）を本番基準**とし、「触れたら約定」は参考値として併記する（オーナー決定 2026-11-06）。比較対象の固定ルール指値スキャルは関門ではなく PPO が超えるべき目標として扱う。

### P2. （参考・判定に使わない）予測可能性チェック
- 各銘柄・各日の T_open+10s〜600s を1秒刻みで、その時点までの情報から特徴量を作り、その後 30s/60s/300s のリターン符号を単純モデル（ロジスティック回帰等）で予測。
- 分割: 日付で時系列分割＋銘柄の一部を学習から外す。
- 合格: 学習外の日・学習外の銘柄で、コスト（往復1呼値）控除後の単純ルール損益がプラス、かつ日次ブートストラップの95%区間が0をまたがない。
- **不合格なら P3 に進まない**（特徴量・データの見直し、または板データ導入を検討）。

### P3. 環境の作り直し
- 1秒ごと判断、行動 Discrete(3)（HOLD / BUY / SELL。建玉中の逆方向は決済、ドテンなし）。
- エピソード = 1銘柄 × 1日（窓 600s、開始 T_open+10s）。報酬 = 合計損益の差分（呼値単位）− コスト。
- P2 で効いた特徴量を採用、観測正規化はモデル内に保存（v1 で実装済みの仕組み）。

### P4. PPO 学習と検証
- 多銘柄プールで学習。合格条件: walk-forward の全区間・学習外銘柄で、Buy&Hold とランダムに勝ち、コスト控除後プラス、1日あたりの売買が過剰でない。
- 乱数の種を変えた複数回学習で再現すること。

### P5. 画面での再生
- `/api/ai/replay-trades` を多銘柄モデルに対応（チェックポイント内の窓・禁止秒数・コスト設定で再生）。

## 4. 未解決・リスク
- 板データ（`S:/jp/stocks_board_*`）は2026年7月の数日〜約1か月分のみ。学習には使えないが、約定の甘さ（最終約定値で成行約定する前提）の検証に使える可能性がある。
- 寄らない銘柄（ストップ高/安張り付き）はその日は売買不可として扱う。
- 歩み値 426GB はネットワークドライブ上にあり、切り出しに時間がかかる（P1 で計測）。
