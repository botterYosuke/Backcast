# 「激しく動く瞬間」に特化したスキャルピング強化学習 — 結果（2026-11-08）

依頼: `rl-burst-task-prompt.md`。経緯: `rl-top50-scalp-handoff.md`。

## 結論（先に）

**判定: 「見つかった」とは言えない（事前に決めた5条件のうち (d) が満たせなかった）。ただし、これまでで一番「惜しい」候補が1つ出た。**

- 強化学習に「片道 1 tick ずれ（往復 2 tick）」という厳しめの約定で練習させると（slip1 版）、エージェントは自分で方策を見つけた。中身は「寄り付き直後の激しい瞬間だけ、まれに入る。直前の動きにやや逆らう向きに入り、損は早めに切り、伸びたら持つ」。
- 事前に1つに決めた方策（slip1・seed 0）は、検証その1と検証その2の両方で、コスト込み **+2.43 / +1.67 tick/回（95%CI 下端 +0.84 / +1.02）** だった。学習外銘柄でもプラスで、買い・売りのどちらでもほぼ同じだけ取れた。
- それでも「見つかった」と言えない理由:
  1. (d) 検証その1で、1日・1銘柄あたりの稼ぎが単純ルールに届かなかった（+0.33 対 +0.42 tick）。
  2. seed のぶれ: 同じ作り方の残り2本は、検証その2で +0.59 / +0.49 tick/回 とプラスだが、95%CI は 0 をまたぐ。
  3. 約定の厳しさに弱い: 1 tick ずれでは、平均はプラスでも CI が 0 をまたぐ（検証その2: +0.64 [−0.01, +1.43]）。「遅れの 200ms の間で一番不利な値段で約定」とすると、3本ともマイナスになる。
- 基準の約定（±0.5 tick）で練習させた版（plain）は、検証その1で +0.5 tick/回、CI もプラスだった。しかし 1 tick ずれや 0.5〜1 秒の遅れで、3本ともゼロ〜マイナスに落ちた。取れていたのは「往復 1 tick の約定が本当にできるなら」という薄い差だった。

## 1. 設定

### 練習場（`src/trading_rl/burst_env.py`、新規）
- **場面**: 前場全体（寄り＋10秒〜11:29）から、「大きく動く瞬間」の検出器が反応した時点を拾い、そこから **60秒を1エピソード** にした。次の反応は、前のエピソードが終わってから拾う（重ならない）。
- **検出器**: 「10秒以内に、直近値が上か下に5 tick 以上動く」を当てる HGB 分類器。
  - 学習期間の既知銘柄 1,200 セッション（4秒おき、266万行）で学習。閾値は、それとは別の学習期間 600 セッションの全秒の点数の上位0.5%（`q=0.995`）。どちらも学習期間の中だけで決めた（`fit_detector` は学習期間外の行を受け付けない。テストあり）。
  - 学習期間内の別セッションでの当たり具合: AUC 0.90。閾値を超えた瞬間の 87% が実際に10秒以内に ±5 tick 動いた（ふだんは 6.7%）。
  - 反応した秒の **89% が寄り後10分** に集中した。また、エピソードの 81〜88% が TOPIX100 銘柄（呼値が細かいので、5 tick が小さな値動きになる）。
  - 保存先: `models/burst/detector_v1.pkl`。
- **注文**: 成行のみ。約定は「判断から 200ms 後の直前の約定値 ± 0.5 tick」（往復 1 tick）。指値は使わない（約定の再現が信用できないため。依頼書の「シミュレーターの穴」）。
- **行動**（毎秒）: ポジションなし → 見送る / 成行買い / 成行空売り。保有中 → 持ち続ける / 成行で決済。60秒目に強制決済。1エピソードの中で何回でも売買できる。
- **観測**（すべてその時点までの情報だけ）: kabu 配信相当にまとめた歩み値から作った 28 個の特徴（`gate_features`）＋ 11 個の細かい値動きの特徴（`fill_model.fill_features_at`）＋ 検出器の点数 ＋ 持ち高・含み損益（tick）・保有秒数・残り時間。
- **報酬**: 決済で確定した損益（コスト込み、tick）＋ 含み損ペナルティ 0.01/秒（前回効いた設定）。報告する損益は常にペナルティなしの生の値。
- **損益の単位**: その銘柄の、反応時点の呼値（tick）。100株あたり。
- **データ**:
  - 学習: 学習期間の既知銘柄のうち、検出器の学習に使っていない 13,854 セッション → 29,126 エピソード（`.cache/trading_rl/burst/episodes_train.npz`）。
  - 検証その1: 2025-07〜12 の全 6,197 セッション（学習外銘柄を含む）→ 8,581 エピソード、124日。
  - 検証その2: 2026-01〜08-19 の全セッション（最後に1回だけ作成・評価）。
- **テスト**: `tests/test_burst_env.py`（17件）。未来の情報が観測に入らない（未来の約定を書き換えても、その時点までの観測が1ビットも変わらない）/ 成行コスト（平らな値動きで往復 −1 tick、ずれ 1 tick なら −2 tick）/ 遅れ・最悪値の約定 / 強制決済 / 報酬の合計＝損益 / 検出器と閾値が学習期間だけ / 保存済みのエピソードの期間 / 高速版ルール評価が1秒ずつ動かす版と一致。

### 比べる相手
- 何もしない / ランダム（毎秒、許される行動から等確率）/ ランダムな向き＋単純ルールと同じ入り時点・出口。
- **単純ルール**: 反応から5秒以内に、直近 m 秒の値動きの向き（順張り）または逆向き（逆張り）に成行で入り、+k tick 利確 / −j tick 損切り / T 秒で決済。1エピソード1回。m ∈ {1,5,30}・順/逆・k, j ∈ {2,3,5,8,なし}・T ∈ {5,10,20,60}・検出器の点数の足切り（なし / 学習期間の反応時点の上位50% / 上位10%）の **1,800 通り** を検証その1の既知銘柄で比べ、tick/回が最も高いもの（売買 500 回以上）を選んだ。

### 強化学習（`scripts/burst/train_burst.py`）
- 自作 PPO（行動マスク付き、1,024 エピソードを同時に動かす）。方策と価値は別々の2層256のネットワーク。γ=1・λ=0.95・クリップ 0.2・エントロピー係数 0.02→0.002。1,510 万ステップ。seed 3本。
- 学習中の検証その1は、学習曲線を描くためだけに見た（保存したのは最後のモデルで、途中のモデルを選んではいない）。
- **基準版（plain）**: 基準の約定（ずれ 0.5 tick・200ms）で練習。
- **厳しめ版（slip1）**: 片道 1 tick ずれ（往復 2 tick）で練習。基準版がストレス試験で崩れたので追加した。

### 2.5 強化学習が覚えたこと（検証その1）
- **plain**:
  - 入る向きは、直前1秒の動きに対してやや逆張り寄り（逆張り 43% 対 順張り 21%）。
  - 出口は「損は早めに切り、伸びた勝ちは長く持つ」。5〜10秒で切った売買は平均 −1.7 tick、30〜60秒持った売買は平均 +6 tick・勝率 63%。
  - 勝ちの平均 +9.0、負けの平均 −8.0 tick で、損小利大の形になっている。
- **slip1**:
  - 反応直後（中央値で14〜17秒目）に、検出器の点数が高い場面だけで入る（入った場面の約9割が、学習期間の反応時点の点数の上位50%）。
  - 入る向きは seed でばらつく。本命の seed0 は、直前5秒の動きに対して 84% が逆張り。seed1 は 68% が順張り。
  - 買いが 75〜98% と偏っている。ただし事後に確かめると、買いも売りも1回あたりの損益はほぼ同じ（検証その1: 買い +2.44・売り +2.36、検証その2: +1.69・+1.63）。
  - 「とりあえず買って11秒持つ」は両期間ともマイナス（−0.67 / −0.76 tick/回）。なので、単なる買い偏りではない。
- 損益の幅がとても大きい（1回で ±90 tick もある）。エピソードの 81〜88% は呼値が細かい TOPIX100 銘柄で、そこでは 1 tick が約 2 bp と小さいため。

## 3. 最終判定（検証その2: 2026-01〜08-19、153日・7,638セッション・36,433エピソード、1回だけ）

方策と判定のしかたを先に `.cache/trading_rl/burst/val2_plan.json` に書いてから、1回だけ評価した（`val2_used.json` で2回目を防いでいる）。
- 選んだ作り方は slip1。plain は検証その1の時点で、(e) を満たせないことが分かっていたため。
- 本命は seed0。検証その1の tick/回 が3本の真ん中の seed を選んだ（一番良い seed は選んでいない）。

|---|---|---|---|---|---|---|---|

- 時間帯別（本命）: 寄り後10分 +1.77 [+1.01, +2.60]（3,914回）/ 9時台 +0.00（349回）/ 10時以降 +2.88 [−0.14, +7.09]（184回）。

- (e) は平均でしか満たしていない。CI まで求めれば満たせない。

## 4. 分かったこと
1. **正直な練習場でも、RL は「自分で方策を編み出す」ところまでは来た。**
   - 単純ルール 1,800 通りの最良は、検証その2で −2.48 tick/回 に反転した（検証その1をたくさん見たことによるまぐれ）。
   - 一方、RL slip1 seed0 は、決め打ちのまま検証その2でも +1.67 [+1.02, +2.47] を保った。
   - 損小利大の出口（早めの損切り・伸ばす利食い）と、「めったに入らない」選び方は、人が教えずに RL が見つけた。
2. **ただし、取り分は約定の厳しさと同じくらいの大きさしかない。**
   - 基準の約定（±0.5 tick）で練習させた版は、往復 1 tick を少し上回る分しか取れず、1 tick ずれや 0.5 秒の遅れで消えた。
   - 厳しめ（往復 2 tick）で練習させると、大きな値動きだけを狙う方策になり、1 tick ずれでも平均はプラスに残った。それでも、遅れの間の一番不利な値段で約定させるとマイナスになる。
3. **激しい瞬間の約定は、今の想定（直前の値段 ±0.5 tick）より悪い可能性が高い。**
   - 200ms の間にも値段が数 tick 飛ぶ。
   - エピソードの 8 割以上を占める呼値の細かい TOPIX100 銘柄では、気配の開きが 1 tick より広いことも多いはず。
   - ここが、結果の一番の不確かさ。
4. **seed のぶれは、前回より小さいが残る。** plain は3本ともそろった。slip1 は売買回数が少ないぶんぶれが大きく、検証その2で CI 下端が 0 を超えたのは本命の1本だけ。
5. **時期による違いが大きい。** 検出器の反応は、2025年後半の 1.4 回/セッションに対し、2026年は 4.8 回/セッション。単純ルールはこの変化で崩れたが、RL slip1 は崩れなかった。

## 5. 次の一手（おすすめ順）
1. **（おすすめ）激しい瞬間の「本当の約定値」を、板の記録で測る。**
   - `S:/jp/stocks_board_kabu_push`（2026-07〜08、14日分）で、検出器が反応した瞬間の気配の開き（何 tick か）と、成行で 100 株を買ったら実際にいくらで約定したかを測る。
   - それを練習場の約定に入れて、slip1 本命をもう一度評価する。この期間は検証その2の中なので、約定の較正だけに使い、成績の判定には使わない。
   - これで「+1.67 が本物か、約定の甘さか」がはっきりする。数時間でできる。
2. 2026-08-20 以降のデータ（オーナーが取り込む最終テスト）で、slip1 seed0 を **作り直さずに** 1回だけ評価する。上の 1 で、約定の想定がだいたい正しいと分かってからが望ましい。
3. seed のぶれを減らす。同じ作り方で seed を 5〜10 本学習させ、多数決で決める方策にして評価する。売買回数が少ない方策ほど、これが効く。
4. 板の記録は、引き続き貯めておく（激しい瞬間の約定を較正するにも、板を見せる方向に進むにも必要）。

## 6. 注意（楽観的になりうる点）
- 検証その1は、ルール選び（1,800 通り）・作り方の追加（plain → slip1）・学習曲線のために、何度も見ている。
- 検証その2は、今回の方策については1回だけ使った。
  - ただし、前の担当の段階②の作業で、別の方策を検証その2で見た記録がある（`.cache/trading_rl/stage2/trips_val2.npz`、`enrich_val2.npz`）。
  - 今回の検出器・閾値・ルール・RL には、それを一切使っていない。
- 約定は「直前の約定値 ± ずれ」で決めている。気配や板は見ていない。自分の注文で値段が動く影響は入っていない（100株なので小さいと考える）。
- 損益は呼値（tick）単位なので、呼値の細かい銘柄の比重が大きい。

## 7. 作ったもの・使い方
- `src/trading_rl/burst_env.py`: 練習場（特徴の計算、検出器、エピソードの切り出し、まとめて動かすシミュレーター、Gymnasium 版、集計）。
- `tests/test_burst_env.py`: 17 件（未来の情報・コスト・遅れ・最悪値・強制決済・報酬・学習期間・ルール評価の一致）。
- `scripts/burst/build_burst.py`: 検出器とエピソードの作成。`detector` / `episodes --split train|val|val2`。
- `scripts/burst/train_burst.py`: PPO。例: `--tag slip1 --seed 0 --steps 15e6 --slip 1.0`。
- `scripts/burst/burst_rules.py`: 何もしない・ランダム・単純ルール（1秒ずつ動かす版と高速版）。
- `scripts/burst/eval_burst.py`: `rules`（総当たり）/ `report --models ...`（検証その1、ストレス試験込み）/ `final --model ...`（検証その2、1回だけ）。
- `scripts/burst/curve_table.py`: 学習曲線の表。
- モデル（`models/burst/`）:
  - `detector_v1.pkl`
  - `ppo_burst_plain_s{0,1,2}.pt`
  - `ppo_burst_slip1_s{0,1,2}.pt`（本命は `ppo_burst_slip1_s0.pt`）
  - `ppo_burst_smoke_s0.pt`（動作確認用の試運転。使わない）
- データ・結果（`.cache/trading_rl/burst/`）:
  - `episodes_{train,val,val2}.npz`、`episodes_train6000.npz`（初回の小さい版。使っていない）
  - `rules_val.json`、`report_val_plain.{md,json}`、`report_val_slip1.{md,json}`、`report_val2_final.{md,json}`
  - `val2_plan.json`、`val2_used.json`、`curve_*.csv`、各ログ
- 実行時間の目安（4コア・3並列）: 検出器 7分。エピソード作成は学習用30分・検証その1 12分・検証その2 17分。PPO は 1,510万ステップで1本47分（3本同時）。メモリは 1 プロセス 1GB 未満。
