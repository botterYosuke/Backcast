# 計画: 数秒スキャルピングAI（指値・板なし）— 2026-11-07 オーナーと合意

目標: 人間のように数秒で数 tick 抜くスキャルピングAI。前提と経緯は `rl-top50-scalp-handoff.md`。

## 出発点の事実
- 成行で入って成行で出る秒スキャは、予測を最大限当てても取れる幅が 0.4〜0.65 tick/回。往復コストは 1 tick なので届かない。追加の情報を足しても短期の予測は良くならない。
- 前回の指値版（`rl-top50-scalp-v2-limit.md`）は、ルール 216 通りで勝ちが 0 通り。PPO は「ほぼ売買しない」に逃げた。負けの原因は逆選択（不利なときにだけ指値が刺さる）。
- 歩み値 `S:/jp/stocks_trades` は 2026-08-19 で終わり。板 `S:/jp/stocks_board_kabu_push` は 14 日分（2026-07-09〜08-28、うち 13 日はテスト期間内）。1日中・約50銘柄・10段。

## 決定事項
| # | 論点 | 決定 |
|---|---|---|
| Q1 | 板を見せるか | **見せない**。歩み値＋指値で挑む |
| Q2 | 約定の判定 | 板の記録で実際の約定率（並び順を含む）を測り、その確率で約定させる中間ルールを**主な判定**に使う。trade_through（厳しめ）と touch（甘め）は参考 |
| Q3 | 最終テスト | **2026-08-20 以降の歩み値を新しく取り込み**、最終テストにする（取り込みはオーナー側）。2026-01〜08-19 は検証期間その2に格下げ |
| Q4 | 合格ライン | 4つすべてを満たすこと: ①最終テストでコスト込み損益がプラス、かつ日ブートストラップ95%CIの下端 > 0（中間約定ルールで判定）②保有時間の中央値 ≤ 10秒 ③1銘柄・1日あたり ≥ 3往復 ④学習外銘柄で損益がマイナスでない。「1回あたり何 tick 取れたか」は記録するだけで、合否には使わない |
| Q5 | 時間帯 | **前場全体（寄り付き〜11:30）**。結果は時間帯別（寄り10分／9時台／10時以降）にも出す |
| Q6 | 進め方 | 段階ゲート: ①上限チェック（10秒先が完全に分かる神様に、中間約定ルールで指値売買させる）→ ②単純な予測＋ルール → ③RL（ルールのまねから始め、seed は最低3本）。前の段階を通過しないと次に進まない |
| Q7 | 本番の証券会社 | **kabuステーション**。AIに見せる情報は kabu の配信から作れるもの（数百msごとのまとめ相当）に揃える。注文が届くまでの時間は、記録ログから実測した値を使う |
| Q8 | 同時保有・資金 | 同時に持つのは最大3銘柄（50銘柄を見て選ぶ）。100株単位。買いと空売り（一日信用）の両方を使う。kabu の発注回数の上限をシミュレーターに組み込む |
| Q9 | 途中で行き詰まったら | **その時に決める**（推奨は、板を見せる方向へ切り替えること。それに備えて、板の記録は続けておくのが望ましい） |
