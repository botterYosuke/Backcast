# 作業依頼: 「激しく動く瞬間」に特化したスキャルピング強化学習（2026-11-08 作成）

## 背景（ここまでに分かっていること）
- **対象**: 毎日、前日の売買代金が上位50の東証銘柄。秒単位で売買し、数秒〜数十秒で数 tick を抜くことを狙う。100株単位。買いと空売り（一日信用）の両方を使う。
- **データ**:
  - 歩み値（約定の記録）は 2024-01-04〜2026-08-19。キャッシュ済みで、前場全体は `.cache/trading_rl_am`、寄り後10分は既存のキャッシュ。
  - 補助の情報（日経・TOPIX の ETF の秒足、同業種、決算など）は `.cache/trading_rl/ext/` にある。parquet には読み取り専用の属性が付いている。
  - 板の記録は 2026-07-09〜08-28 の14日分しかなく、学習には使えない。
- **期間の分け方**: 下の3つ以外の期間は使わない。

  | 用途 | 期間 | 使い方 |
  |---|---|---|
  | 学習 | 2024-01-04〜2025-06-30 | |
  | 検証その1 | 2025-07-01〜2025-12-31 | 選ぶ・調整する |
  | 検証その2 | 2026-01-01〜2026-08-19 | 確かめる。最後に1回だけ |

  2026-08-20 以降は、将来オーナーが取り込む最終テストのために取ってある。さらに、銘柄の約20%は md5(stem) による「学習外銘柄」になっている（`trading_rl.scalp_env.is_heldout`）。
- **シミュレーター**: `src/trading_rl/scalp_env.py` の `ScalpEnv`（Gymnasium）。
  - 成行の約定は「注文が届いた時点（既定200ms後）の直前の約定値 ± 0.5 tick」で決まる。往復で 1 tick のコストになる。
  - 指値の約定は `fill_rule="queue_est"`（板の記録で較正した中間ルール）で決まる。

**これまでの結論**（詳細は「読むもの」を参照）:
1. 成行で入って成行で出る秒スキャは、教師あり予測で取れる値動きが 0.4〜0.65 tick/回にとどまり、往復コストの 1 tick に届かない。追加の情報（指数、同業種など）を足しても、数秒先の予測は良くならない。
2. 指値は、予測が外れた場面でだけ約定する（逆選択）。予測が出た秒全体では +0.64 tick だが、約定した場面だけで見ると −0.28 tick。ルール 40 通りすべてマイナス。
3. 損の大きさは、その瞬間の値動きの激しさに比例する。激しい瞬間は勝ちも大きいが、負けがそれより一回り大きい。損切り・利確・保有時間の決済ルールを 224 通り試しても改善は最大 0.1 tick ほどで、損の原因は入り方にある（`scripts/probes/stage2_exits.py`）。
4. **シミュレーターの穴**: queue_est の「その場で約定」は、その後の値動きと無関係なくじ引き（`ScalpEnv._place` の `rng.random() < pmkt`）。この部分がプラスに見えても、作り物である。
5. 過去の強化学習（自作 PPO＋行動マスク、ルールのまね BC から開始）は、seed のぶれが情報の差より大きかった。また「ほぼ何もしない」に逃げやすかった。
6. **手がかり**:
   - 「数秒後に大きく動く瞬間」は、HGB 分類器で強く当たる（AUC 0.8 以上。`scripts/probes/probe_jump.py`）。ただし、上げと下げがほぼ同じ割合で起きる。当てているのはボラティリティの急上昇で、方向は当てていない。
   - 寄り後10分の自信上位0.1%で「成行で入り、+5 tick に届いたら即決済」とすると、コスト込みで +1.4 tick/回、95%CI [+0.2, +2.7] だった。ただし、18 通りのうち最良の結果を見たもので、約定は楽観的に仮定し、検証その1を何度も見ている。本物かどうかは未確認。

## Goal（目的）
- オーナーの希望は「AlphaGo のように、AIに自分で方策を編み出させたい」こと。具体的には、**激しく動く瞬間に、方向の読み方と損小利大の出口を、強化学習エージェントが自分で見つける**ことを狙う。
- そのために、**シミュレーターの穴を突けない「正直な練習場」**を作る。その上で RL を学習させ、見つけた方策が本物かどうかを、厳しい基準で判定する。
- 結果がプラスでもマイナスでも、平易な日本語の報告書にまとめる。

**推奨する設計**（変えてよいが、変えた理由を記録すること）:
- **注文**: 成行のみ。指値は使わない（約定の再現が信用できないため）。
- **練習の場面**: 激しい瞬間だけを練習させる。
  - 学習期間だけで学習した「大きく動く瞬間」検出器（probe_jump.py の考え方。閾値は学習期間の分位）が反応した時点から、例えば 60 秒を 1 エピソードにする。
  - 前場全体（寄り＋10秒〜11:29）から場面を集める。
- **行動**:
  - 平らな時（ポジションなし）: 見送る / 成行買い / 成行空売り
  - 保有中: 毎秒（または 0.5 秒ごと）、持ち続ける / 成行で決済
  - エピソード終了時は強制決済する。
- **報酬**: 確定した損益（コスト込み）を基本にする。「何もしない」への逃げや、塩漬けへの対策は、過去の知見（`rl-top50-scalp-handoff.md` の「報酬設計で分かったこと」）を参考にする。例えば、含み損ペナルティは効いた。
- **観測**: すべて因果的な特徴（その時点までの情報だけ）。既存の `scalp_features.py` / `fill_model.fill_features_at` / 検出器のスコアを使う。保有中は、含み損益と保有秒数も見せる。
- **比べる相手（ベースライン）**:
  - 何もしない
  - ランダム
  - 単純なルール（検出器が反応したら、短期の値動きの向きに成行で入り、+k tick 利確 / −j tick 損切り / T 秒で決済）。ルールのパラメータは検証その1で選ぶ。

## Constraints（制約）
- **読み取り専用（変更・削除・移動の禁止）**: `S:` ドライブと `_Merino` 以下。
- **ネットワークドライブ**: 広い範囲の検索（再帰 grep や find）をしない。
- **models の上書き禁止**: 新しいモデルは `models/burst/` に、新しい名前で保存する。既存の `models/*.pt`、`models/screen/*.pt`、`.cache/trading_rl/stage2/*`、`.cache/trading_rl/fillcal/*` は上書きしない。
- **他の作業者のファイル**: 変更しない。対象は `scripts/probes/fill_calib*.py`、`stage2_trends.py`、`stage2_trade.py`、`predict_am.py`、`oracle_upper.py`。共有モジュール（`scalp_env.py` など）を変えるなら、既存テストを壊さない後方互換の形にする。テストは `uv run pytest tests/test_scalp_*.py tests/test_ai_replay_api.py tests/test_predictor_replay.py -q`。
- **プロセス**: 自分が起動したもの以外は止めない。サブエージェントを使う場合も、サブエージェントにプロセスを止めさせない。
- **メモリ**: このPCは 20GB・4コア。並列は最大3ワーカー。以前、メモリ不足で Claude Code に学習を止められたことがある。メモリ不足で止められた場合、オーナーの指示なしに再起動しない。
- **Git**: コミットはしない（オーナーが指示したときだけ）。
- **期間**: 検証その2（2026-01〜08-19）は、方策を1つに決めた後に1回だけ使う。2026-08-20 以降のデータは扱わない。学習・閾値・正規化は、すべて学習期間だけで決める。
- **実行**: リポジトリ直下で `uv run python ...` を使う。`src` を import するには `sys.path.insert(0, "src")` か `PYTHONPATH=src` が必要。Windows なので、出力が文字化けする場合は `PYTHONIOENCODING=utf-8` を付ける。
- **報告の書き方**: オーナーへの報告は、専門用語を並べない平易な日本語で書く。判断を求めるときは、おすすめを添える。
- **楽観的な仮定を見逃さない**: 激しい瞬間ほど、注文が届くまでに値段が飛ぶ。成行の約定（直近値 ±0.5 tick、200ms）は、この場面では甘い可能性がある。

## Acceptance criteria（完了条件）
次をすべて満たしたら完了とする。

1. **練習場**
   - 激しい瞬間に特化した環境を、新しいファイルとして作る（例: `src/trading_rl/burst_env.py`）。
   - pytest のテストを付ける。少なくとも次を確かめる: 未来の情報を観測に入れていないこと / 成行コストが正しいこと / エピソード終了時に強制決済されること / 検出器と閾値を学習期間だけで作っていること。
   - 既存のテストがすべて通ること。
2. **ベースライン**: 何もしない・ランダム・単純ルールについて、検証その1の成績を出す。
3. **RL の学習**
   - seed を3本以上で学習し、学習曲線とモデル（`models/burst/`）を残す。
   - 「ほぼ何もしない」に逃げていないかを、売買回数で確認する。
4. **成績の報告**: 検証その1について、次の指標を出す。どれも日ブートストラップの95%CI付き。
   - コスト込み tick/回 と、tick/日・銘柄
   - 売買回数
   - 勝率
   - 保有時間の中央値
   - 既知銘柄と学習外銘柄の別
   - 時間帯別（寄り後10分 / 9時台 / 10時以降）
5. **ストレス試験**: 約定を不利にしても残るかを試す。少なくとも、成行のずれを片道 0.5 → 1 tick にした場合と、注文が届くまでの時間を 200ms → 1秒にした場合。
6. **最終判定**
   - 方策を1つに決めてから、検証その2で1回だけ評価する。
   - 「見つかった」と言ってよいのは、次の (a)〜(e) をすべて満たしたときだけ。満たさなければ、正直に「見つからなかった」と報告する。
     - (a) 検証その1と検証その2の両方で、コスト込み tick/回の95%CI下端が 0 を超える
     - (b) 3本の seed すべてでプラス
     - (c) 学習外銘柄でマイナスでない
     - (d) 単純ルールのベースラインを上回る
     - (e) ストレス試験の少なくとも「1 tick ずれ」でプラスが残る
7. **報告書**
   - `.agents/docs/research/rl-burst-results.md` に書く。中身は、設定 / 結果の表 / 判定 / 分かったこと / 次の一手のおすすめ。すべて平易な日本語で書く。
   - `.agents/docs/research/rl-top50-scalp-handoff.md` の末尾に、要約と、触ったファイルの一覧を追記する。
