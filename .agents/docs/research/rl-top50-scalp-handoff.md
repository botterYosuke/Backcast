# 引き継ぎ: top50 寄り付き10分スキャルプ RL（2026-11-07 時点）

## ゴールと前提
- 対象: 毎日の前日売買代金上位50銘柄。T_open+10s〜+600s のみ売買、600s で強制決済。1秒ごとに判断。
- 現行の主設定: 成行モード（keep / market_buy / market_sell / market_flatten）。コストは片道 0.5 tick（直近約定値基準）＝**往復 1 tick**。
- 分割: train 2024-01-04..2025-06-30 / val 2025-07-01..2025-12-31 / **test 2026-01-01..2026-08-19（未使用。最後に1回だけ）**。銘柄の約20%は md5(stem) で held-out。
- 判定は val のみ。主指標は「1往復あたりの取り幅（コスト前、gross ticks/trip）」と、コスト込みの円/セッション（100株）。
- アプリで目視: `uv run python run.py` → http://127.0.0.1:8765/ → 「🤖 AI Play: ON」→ プルダウン。`models/screen/*.pt` も「ふるい分け（成行・<情報>）」として出る（server.py を本セッションで修正）。
- 制約（オーナー指示）: `S:` と `_Merino` は読み取り専用 / models の上書き禁止 / 無断コミット禁止 / ネットワークドライブの広域検索禁止 / サブエージェントはプロセスを殺さない / 説明は平易な日本語で、判断には推奨を添える。

## 報酬設計で分かったこと（詳細は rl-top50-scalp-v2-*.md）
- 「状態（持っている/いない）」ではなく「行動」に罰・報酬（keep penalty / action bonus）。
- 実現損益のみの報酬 + γ<1 → 塩漬け（損失の先送り）。γ=1,λ=1 でも保有が長い → **含み損ペナルティ（0.01/s）で解消**。
- 現行の共通引数: `--order-mode market --reward-mode realized --gamma 1.0 --gae-lambda 1.0 --unrealized-loss-penalty 0.01 --inventory-penalty 0 --idle-penalty 0 --keep-penalty 0 --action-bonus 0.25 --fill-curriculum 0.0,0.5 --ent-start 0.03 --ent-end 0.005 --bc-from rule --bc-steps 2000 --bc-sessions 300 --bc-critic`
- 「1日1回しか取引しない」の正体: 寄り付き10秒後に1回入り、その後は P(keep)≈0.8〜0.85 で argmax が keep。確率どおりにサンプリングすると1日60〜70回売買する（=学習中の挙動）。アプリ再生と評価の取引数は完全一致（バグではない）。

| 何秒先 | IC（base） | IC（全部入り） | 自信上位5%の取り幅（コスト前） |
|---|---|---|---|
| 1s | 0.095 | 0.098 | ≈0.4 |
| 2s | 0.078 | 0.080 | ≈0.4 |
| 5s | 0.058 | 0.053 | ≈0.4〜0.5 |
| 10s | 0.045 | 0.039 | ≈0.2〜0.4 |
| 20s | 0.028 | 0.033 | ≈0〜0.25 |

- 短期（1〜20s）の予測力は base（銘柄自身の直前値動き）だけで決まり、追加情報は効かない。取り幅は最大 0.5〜0.65 tick で往復 1 tick に届かない。おそらく bid-ask bounce（成行では取れない）。
- 長め（2〜10分）では指数情報 K・N が効く。
- 予測→売買のテスト（probe_trade.py: train 分位で閾値、成行で入り120s保有、コスト込み）: base は明確に負け、K/N で損が半減。E+F+K+N+P の上位1%で +2.84 tick/回 だが **20セッションに1回・CI が 0 をまたぐ**、held-out はほぼ 0。→ 未確認。

### 実行中: 「数秒後に大きく上げる瞬間」を捉えられるか（probe_jump.py）
- 事象: 今後 h 秒以内の最高値 − 現値 ≥ k tick（(h,k) = (3,3),(5,3),(5,5),(10,5)）。HGB 分類器、閾値は train 分位、成行で入り h 秒後に成行で出る（net = 値動き − 1 tick）。日ブートストラップ CI。
- 結果（val 2500 セッション、2秒おきに判定点）:

| 事象 | 平常時の発生率 | AUC | 上位1%: 的中率 / 保有して売る net（tick, CI） | 上位0.1%: 的中率 / net（CI） |
|---|---|---|---|---|
| 3秒以内に+3tick | 10.4% | 0.81 | 0.55 / −0.15 [−0.47,+0.20] | 0.62 / +0.65 [−0.44,+1.74] |
| 5秒以内に+3tick | 15.9% | 0.80 | 0.64 / −0.05 [−0.47,+0.37] | 0.70 / +0.09 [−1.15,+1.34] |
| 5秒以内に+5tick | 6.7% | 0.85 | 0.53 / −0.13 [−0.62,+0.33] | 0.65 / +0.96 [−0.38,+2.46] |
| 10秒以内に+5tick | 12.8% | 0.82 | 0.65 / +0.32 [−0.49,+1.16] | 0.71 / +0.55 [−2.37,+3.39] |

  （base の値。O/K/C/全部入りもほぼ同じ AUC。上位0.1%の net は O や全部入りで CI が 0 を少し超える行が2つあるが、40通り比べた中の2つなので偶然の範囲。）
- 解釈: 「大きく動く瞬間」は base だけで強く当たる（AUC 0.8 超、的中率は平常時の4〜8倍）。ただし方向まで当たっているかは未確認（ボラ急上昇の瞬間は上にも下にも大きく動く）。h 秒保有して成行で出る形ではコスト込みで有意なプラスにならない。
- 追試（`scripts/probes/probe_jump.py` 改訂版、2026-11-08 完了。メモリ約 3〜4GB）: 同じ瞬間に「大きく下げた」割合（down）と、+k tick 到達で即成行売り（TP、net は往復1tick込み）。

| 事象 / 情報 | 上位1%: up / down / TP net [CI] | 上位0.1%: up / down / TP net [CI] |
|---|---|---|
| 5s+3tk base | 0.64 / 0.54 / +0.15 [−0.22,+0.52] | 0.70 / 0.55 / +0.54 [−0.69,+1.64] |
| 5s+5tk base | 0.53 / 0.45 / +0.08 [−0.31,+0.48] | 0.65 / 0.45 / +1.31 [−0.05,+2.57] |
| 5s+5tk O | 0.53 / 0.45 / +0.05 | 0.64 / 0.44 / **+1.43 [+0.21,+2.70]** |
| 5s+5tk ALL | 0.53 / 0.45 / +0.09 | 0.65 / 0.45 / **+1.45 [+0.53,+2.48]** |
| 10s+5tk ALL | 0.65 / 0.57 / +0.17 | 0.72 / 0.57 / **+1.63 [+0.34,+3.63]** |

- 解釈: 選ばれた瞬間は「上にも下にも大きく動く」瞬間（down が up とほぼ同率）＝主に**ボラティリティの急上昇を当てている**。方向は少しだけ上寄り。利確の形で、上位0.1%（約60日に分散、約350〜390回）に CI が 0 を超える行が出た。ただし (1) 18セルから最良を見ている、(2) 判定時点の last±0.5tick で約定する仮定は、まさに急変動の瞬間で最も楽観的、(3) val を何度も見ている。
- 次に確かめるべきこと: 約定を1〜2秒遅らせても残るか（遅延耐性）、2024〜2025 を半年ずつ walk-forward して毎期残るか。

## 次の候補（オーナー判断待ち）
1. **数分保有 × 指数情報**: 2024〜2025 を半年ずつ4分割して walk-forward（前で学習→次の半年で検証）。上位1% +2.8 tick が本物か確かめる。手元データで約30分。
