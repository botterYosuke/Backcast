# ヤーマン氏の約定 -> 行動模倣 (BC) CSV 変換

- 元: `_Merino/docs/human_trader/fills.csv` (読み取り専用)。変換: `scripts/convert_human_trades.py`、テスト: `tests/test_convert_human_trades.py`。
- 出力 (`.cache/trading_rl/human/`、gitignore 済み):
  - `yaman_trades.csv`: `scalp_bc.py` の `--bc-from csv:<path>` 形式 (`date,stem,us,side,price,qty,kind,order`)。
  - `yaman_exclude_sessions.csv`: `date,stem` 37 件 (リーク防止リスト)。
  - `yaman_fills_detail.csv`: 全約定の照合結果 (品質・出所・フラグ。監査用)。
- 再実行: `uv run python scripts/convert_human_trades.py` (キャッシュが伸びたら再実行すれば増える)。

## 変換の規則

1. 東証の 新規/返済 のみ使う。PTS 11 行、現物 3 行は対象外 (ペアにしない)。
2. 新規->返済を (日付, 銘柄, 方向) ごとに FIFO で組む (`human_trader_roundtrips.py` と同じ。同一分内で返済が先に並んだ場合は新規を待つ)。当日に建玉のない返済 (持ち越し・窓前の建玉) は往復にならないので出力しない。
3. 約定秒の復元: 約定の分に入るキャッシュ tick のうち価格 == 約定単価で最初のもの。直前に割り当てた時刻以降に限る (順序保存)。なければ 1 tick 以内で最も近い価格。`us` は tick の epoch_us。
4. 往復 (レグ) が使えるのは、両約定が照合済みで、両方とも [T_open+10s, T_open+600s] に入り、建て <= 返済、備考に矛盾フラグがない場合。使えるレグの約定だけを 1 回ずつ出力する。
5. 備考の矛盾フラグ (指値より上/下で約定、受付より前、逆指値、表示ずれ、読み取り不能、取消済、画面は…等) があるレグは捨てる (今回は 1 レグ)。
6. `order` 列は全行 `market`。彼の注文はすぐ約定する指値で成行に近く、ローダーの自動判定 (last±slip と一致するか) に任せると買いの約定が `bid_k0` (待つ指値) になり実態とずれるため。ローダーは `qty` を読むが方向しか学習に使わない (100 株単位)。

## 注意

- 分解像度: 秒は「その分の最初に価格が合う tick」に過ぎず、実際の約定秒と最大 59 秒ずれ得る。特に 09:00 台は寄り直後 (T_open+10s より前) に誤って置かれ、捨てられやすい (建て 20 件)。
- 同じ価格の tick が分内に複数あれば最初のものを選ぶので、建ての時刻はやや早め、直後の返済との間隔はやや短めに偏る。
- 往復の途中で窓 (10 分) を越えた建ては、返済が窓外なので出力しない (出すと「強制手仕舞いまで持つ」教師になる)。
- 複数ロット (100 株 x 4 など) を段階的に建てた場合、環境は 1 単位しか持てないので、2 本目以降はローダーが違法として落とす。
- 画像出所は転記の矛盾を含む (README の「注意」)。往復の約定時刻が分単位で合わない行は unmatched として落ちる。
- 先行分析では彼の日中売買に優位性は見つかっていない。このデータは探索の事前分布 (実際に動く売買の形) であり、腕前の正解ラベルではない。
